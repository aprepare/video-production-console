# 开箱配置实施计划

> 执行方式：按 `executing-plans` 推进；独立检测与配置码模块按 `dispatching-parallel-agents` 并行实现，由主代理复核后集成。

**目标：** 完成 `../../../../TASK.md` 的后端开箱配置功能及全部验收，不修改前端。

**架构：** 剪映系统发现保留在 `jianyingdraft`；配置码保留在 `settings`，复用现有原子保存和密钥保护；`setup` 编排配置检查、模型查询和检测结果应用。HTTP 层只解码与映射错误，启动预置在首次创建 Runtime 快照之前执行。

**技术栈：** Go 1.25、net/http、modernc SQLite、Windows registry、标准库 gzip/base64。

## 约束

- 所有测试使用临时目录和本地假服务，不接触真实 `video-console-data/`。
- 不输出密钥、配置码或上游错误中的完整 URL；机器档案路径须解析联接后位于 DataRoot 内。
- 不执行 git reset/checkout/restore/stash/clean；最后统一按指定消息提交，不 push。
- `CODEX_RESULT.md` 在提交之后生成，保留在根目录且不提交。

## 1. 剪映发现（独立模块）

- 文件：`internal/jianyingdraft/detect*.go`。
- 接口：`Detect() (Detection, error)`，结构遵循 TASK.md。
- 先测 INI、root_meta、多来源真实路径去重、数字版本选择，再实现平台发现与进程探测。
- Windows 系统调用通过可替换函数隔离；非 Windows 返回非 nil 空候选。
- 验证：`go test ./internal/jianyingdraft/...` 和 Linux 交叉 vet。

## 2. 配置码（独立模块）

- 文件：`internal/settings/activation*.go`。
- 接口：`Service.ActivateCode(ctx, code)`、`Service.ExportCode(ctx, ExportCodeRequest)`、`Service.AutoActivate(ctx, dataRoot)`。
- 先测往返、拒绝本机键、过期、analysis skipped、两级限长、无值回显、导出筛选、首启哈希去重，再实现。
- 更新必须使用当前保存的公共值合并，通过一次 `Update` 写入。首启不调用 Runtime，避免提早冻结运行配置。
- 验证：`go test ./internal/settings/...`。

## 3. 配置检查与模型列表

- 文件：`internal/settings/setup_access.go`、`internal/setup/{service,status,models}.go` 及测试。
- 设置只增加读取最新保存密钥的方法；不绕过密钥白名单或修改运行快照。
- `setup.NewService(settings, Options)` 注入检测函数、HTTP 客户端和时钟；`Status(ctx)` 输出固定顺序的 11 项。
- 单项 4 秒并发检查，父请求取消生效；中文静态错误、平台状态用已知 ID 翻译，禁止回传上游文本。
- `Models(ctx)` 按规范化地址和密钥哈希合并请求、5 秒超时、5 分钟缓存；配置变化即时隔离缓存。
- 先用 httptest 与临时文件覆盖完整就绪、可选缺失、版本警告、服务错误、请求超时、去重和缓存过期，再实现。

## 4. 检测应用、HTTP 与首启

- 文件：`internal/setup/jianying.go`、`internal/httpapi/setup.go`、`internal/app/app.go`、`cmd/console/main.go` 及测试。
- `Detect(ctx)` 添加当前保存路径及匹配状态；`ApplyJianying(ctx, root)` 重新检测、只接受候选、同步 DataRoot 内现存机器档案。
- JSON 用 RawMessage 读改写，保持未知字段及大整数；在目标目录创建临时文件后 rename 替换。
- `AutoDetectJianying(ctx)` 只在空配置且唯一 HasRootMeta 候选时应用，不覆盖已配路径。
- 注册全部 `/api/setup/*` 与检测路由，沿用应用外层会话及 CSRF 中间件，响应设置 no-store。
- 首启先激活再检测，随后创建 Runtime；失败日志使用固定中文说明。
- 从已保存的 Public.DataRoot 读取首启配置码，覆盖启动默认目录与持久化目录不同的情况。
- `internal/localpath` 统一解析本次功能的真实路径；Windows 用文件句柄补足 Go 1.25 对 junction 的解析，分别测试 symlink 与 junction。
- 测试任意路径拒绝、重新检测、档案字段保留/越界联接不写、空配置唯一候选、真实重启状态、HTTP 解码上限与鉴权。

## 5. 验收与交付

- 复核两个独立模块的关键实现及测试，修复遗漏。
- 执行 `go build ./...`、`go vet ./...`、`go test ./internal/...`、`GOOS=linux go vet ./internal/jianyingdraft/...`，另测改动的 console 启动逻辑。
- 临时 go run 只读调用本机 `Detect()`，保存输出供报告，运行后删除临时程序。
- 检查差异没有前端、真实数据或临时产物，运行指定 `git add -A` 和 `git commit -m "feat(setup): jianying auto-detect, setup checklist, activation codes"`。
- 根目录生成未提交的 `CODEX_RESULT.md`，记录接口示例、实际测试结果、已知限制与实机检测输出。
