# 默认二创写手提示词（无后台质检）

日期：2026-08-25  
范围：控制台默认二创（`remix.standard` / `remix.review`，`remix_prompt_style=rewrite`）  
状态：设计已口头确认，待实现

## 1. 要解决什么

日产风景混剪的流量上限在文案。当前默认写手工单过长、禁令互殴，模型为了「别犯错」把稿写成理财科普；同时旧质检（字面重合 40%、质检模型返工、旧爆款开场闸）一改稿就更容易写软。

操作员最烦的顺序：写软 → 换题（开头 / 中间 / 答案被说圆 / 结尾）→ 开头费劲。洗稿不是当前痛点。狠和懂打架时选狠。「钱出事了」只是举例，不是所有稿的开头公式。

不要加人工程序：一次点击，一次出成稿，操作员自己通读。

## 2. 拍板

| 项 | 决定 |
|---|---|
| 界面 | 不变。不弹机器卡，不多一步确认 |
| 模型调用 | 写手一次出连续口播 + 标题描述。无判官、无自动重写 |
| 旧质检 | **整段去掉**（默认 rewrite 路径） |
| 字面重合 40% | **删除**，不再查、不再为压重合返工 |
| 课名 / 橱窗 / 卖课位置 | 只写在提示词里，**不再用程序改稿** |
| 锋利版 `rewrite_sharp` | 提示词本轮不改 |
| `copy` 组装线 | 本轮不改（含它现有的后处理，若与 rewrite 共用函数则分支跳过 rewrite） |
| 对标进化 | 实现后用同一篇原文跑旧/新提示词，并排看前 3 句，按败因改提示词再跑 |

曾考虑「写完再判、不过关重写一次」，已明确取消。

## 3. 写手工单（默认 rewrite）

成功标准（只 4 条，写在工单最前）：

1. 前 3 句与原稿同一件事，力度不输原稿第一句的狠法（截止日仍是截止日，数字砸仍是数字砸）。
2. 开场切口必须换：现场、人物、用词都换，禁止同义改写原稿第一句。
3. 原稿故意不说完的答案继续藏着；关键数字原词保留，周围句子重说。
4. 禁止写成理财课、讲解员、家庭提醒。狠和懂打架，选狠。

第 1 条或第 4 条不像 → 整篇重写，不要局部补两句。

硬底线（短）：不换题、不降温、不补圆答案、篇幅约 0.8～1.2 倍、课名《财富觉醒方法论》全文一次、主页橱窗一次、卖课只在最末最多四句。

从通用工单删除或后置：

- 开场禁词清单（锚点、换锚、货币、认知等）不再当开头死刑
- 「前 3 句必须再钉一次未揭晓答案」（避免开头把包袱说漏）
- 「40 字内必须听懂谁的钱出事了」（举例，不是公式）
- 旧爆款专用禁令（2 万亿去哪了、房股市黄金、50–77 万亿）

样品（对标到来前用占位，到来后换成真句）：

- 坏：共情、提醒、讲概念、同义改写原稿第一句
- 好：前 3 句能听出原稿那件急事，切口已换，答案未破

JSON 契约保持现有字段：`continuous_script`、`titles`、`short_titles`、`descriptions`、`topics`、`cta`。标题仍从本篇口播长出；发布外壳仍不写课名 / 橱窗 / 上车。版本戳固定为 `语感回流 2026-08-25 去质检`，写入 `remix_run.json` 便于和旧稿对照。

## 4. 默认路径要拆掉的后处理

`remix_prompt_style=rewrite` 写完后，**不再**调用：

- `repairRemixDraft` / `repairSourceOverlap`（含质检模型、40% 覆盖、长句重合返工）
- `inspectCopyIssues` / `applyLocalCopyFixes` / `buildCopyRepairPrompt`（课名年份、重复卖课、定存区间、旧开场切口、开头必须含问号或「万亿」「存」）

解析 JSON、落 `continuous_script.txt`、写 `result.json` 信封照旧。任务结果不必再为重合百分比或旧质检失败而整单失败。

实现时在 `run.go` 对 rewrite 跳过上述函数；`copy` 若仍走同一入口，用 style 分支，不要误伤 copy。单测：默认 rewrite 即使字面重合高、开头没有「万亿」，只要 JSON 合法即交付。`overlap_test.go` 里针对 rewrite 交付路径的期望要改掉或改测「跳过」。

设置页的「质检模型」字段本轮可以留着（copy / 旧配置），但默认 rewrite 不读它。

## 5. 不改

- 登录后风景混剪默认入口、图文 ZIP、已屏蔽的电影 / 图文视频
- 口播切句 `remix.spoken_lines`、配音、混剪、剪映登记
- 选题、二创改回 Codex、设置页 runtime 大改
- `docs/项目说明.md` 里过时的旧戳，实现时顺手改成新戳即可，不做文档大翻修

## 6. 实现后怎么验收

自动：`go test ./internal/agentruntime/openaicompat`（提示词含 4 条成功标准、不含开场禁词死刑和 40 字公式；rewrite 路径不跑重合闸）。

人工：同一篇同行原文，旧提示词一稿、新提示词一稿，只看前 3 句是否更狠、是否仍是原稿那件事。操作员给对标和模型后，把占位样品换成真句，再跑同一套对照。

## 7. 风险

没有判官，写软和换题只能靠提示词和人通读。这是明确取舍，不是遗漏。重合不再拦，发稿前的平台风险由操作员自己看。
