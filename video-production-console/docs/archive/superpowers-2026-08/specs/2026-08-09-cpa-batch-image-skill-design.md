# CPA 批量生图 Skill 设计

## 目标

创建用户级 Skill `cpa-batch-image`。当用户说“批量生图”“批量生成图片”“一次生成多张图片”“根据文案配图”等表达，并且希望通过现有 CPA 服务调用 `gpt-image-2` 时，Codex 应自动加载该 Skill，实际发送生图请求、保存图片并报告逐张结果。

Skill 同时支持两种输入：

1. 用户直接提供多条生图提示词。
2. 用户提供一篇文案，由 Codex 先拆解为多条互不重复的配图提示词，再执行批量生成。

Skill 安装到 `C:\Users\prepare\.codex\skills\cpa-batch-image`。它是 CPA 批量生图的专用执行路径；用户明确触发本 Skill 时，不改走系统内置的普通 `imagegen` 路径。

## 非目标

- 第一版只支持文生图，不支持参考图编辑、局部重绘和透明背景。
- 不在 Skill 内保存 API Key。
- 不把多个不同提示词合并为一个 `n > 1` 的请求。
- 不创建常驻 Web 服务或新的远程任务队列。
- 不修改 CPA 服务器配置、账号轮询策略或 OAuth 文件。

## 目录结构

```text
cpa-batch-image/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── scripts/
│   └── batch_generate.py
└── references/
    └── input-schema.md
```

`SKILL.md` 负责触发、输入收集、文案拆图、执行顺序、等待和结果交付。`batch_generate.py` 负责确定性的并发、HTTP 请求、重试、编码校验、图片落盘和清单记录。`input-schema.md` 只保存提示词输入文件与结果清单的结构，避免主 Skill 过长。

## 配置

运行时读取以下环境变量：

- `CPA_API_KEY`：必填。缺失时停止执行，提示用户在本机设置，不要求用户在对话中粘贴密钥。
- `CPA_BASE_URL`：可选，默认 `http://23.138.12.112:8317/v1`。

默认请求参数：

```json
{
  "model": "gpt-image-2",
  "n": 1,
  "size": "1024x1024",
  "quality": "low",
  "output_format": "png"
}
```

用户可以修改尺寸和质量，但模型固定为 `gpt-image-2`，每个 HTTP 请求固定 `n=1`。不同提示词始终拆成不同请求，使 CPA 的 round-robin 调度可以按请求选择账号。

## 输入处理

### 提示词列表

接受用户直接粘贴的编号列表、Markdown 列表或结构化 JSON。Codex 将它们规范化成 UTF-8 JSON 输入文件，每项至少包含稳定编号和 `prompt`。

### 文案自动拆图

用户提供文案时，Codex先根据内容顺序拆成视觉信息互不重复的提示词：

- 用户指定数量时严格使用该数量。
- 用户未指定数量时默认 6 张。
- 每条提示词必须独立完整，不引用“上一张”“同上”等跨图上下文。
- 用户要求画面文字时，原文逐字保留，并单独标识 exact text。
- 用户未要求画面文字时，默认不主动加入大段中文排版，避免生成文字失真。

生成请求前，Codex先向用户简要展示数量、尺寸、质量、并发上限和输出目录；已有明确参数时无需再次提问。

## 波次调度与全局并发

批量任务采用固定波次，不采用“完成一个立即补一个”的滑动窗口：

1. 每批最多并发发送 10 个独立请求。
2. 等待本批所有任务成功、失败、完成内部重试或达到单请求超时。
3. 如果还有下一批，等待 3 秒。
4. 发送下一批最多 10 个请求。
5. 最后一批完成后直接汇总，不再额外等待。

例如 25 张图片：

```text
第 1 批：10 张全部结束 → 等待 3 秒
第 2 批：10 张全部结束 → 等待 3 秒
第 3 批：5 张全部结束 → 汇总
```

默认并发为 10，允许用户调低到 1～10，但拒绝大于 10 的值。

为防止两个 Skill 调用各自并发 10 而形成 20 个在途请求，执行器必须持有跨进程全局批次锁。锁覆盖整个批量任务；第二个任务等待前一个任务释放锁后再开始。锁等待可被用户取消，异常退出时必须可靠释放。

## 超时和等待

- 每个 CPA HTTP 请求的完整读取超时为 180 秒。
- 批量任务不设置 30～35 秒的总硬超时。
- 每个请求拥有独立的执行上下文；一个任务失败不能取消其他任务。
- Codex 启动长任务后持续等待执行器完成，并在超过 60 秒时向用户提供简短进度更新。
- 如果运行环境本身无法维持超过 35 秒的进程，Skill 必须报告该外层限制，不得谎称已经设置成功。

## 重试规则

每张图片最多额外重试一次，且重试发生在当前波次内部：

- `408`、`429`、`502`、`503`、`504` 可以重试一次。
- 普通 `500` 只有在响应正文不包含 `context canceled` 时才可重试一次。
- `429` 优先遵循 `Retry-After`；没有时等待 10～20 秒随机退避。
- `context canceled`、客户端超时、`AbortError`、认证错误、参数错误和内容策略拒绝不得自动重试。
- 重试仍使用一个新的独立 HTTP 请求，但保留同一个任务编号并在清单中增加重试计数。

## UTF-8 与乱码防护

批量请求必须使用：

```text
Content-Type: application/json; charset=utf-8
```

JSON 必须以 Unicode 字符串构造，使用 UTF-8 字节发送。禁止经过 Latin-1、GBK 或重复 encode/decode 转换。

执行器在发送前检查常见乱码特征，例如密集出现 `鈥`、`鍏`、`涓`、`滄` 等异常序列。发现疑似乱码时整批预检失败并指出任务编号，不允许把损坏的提示词提交给 CPA。提供显式覆盖参数仅用于确认属于正常文本的极少数情况。

## 响应、保存与恢复

成功响应优先读取 `data[0].b64_json`，进行严格 Base64 解码并验证文件非空。输出默认保存到当前项目：

```text
output/cpa-batch-image/<YYYYMMDD-HHMMSS>/
```

目录内容：

```text
001.png
002.png
prompts.json
manifest.json
```

`manifest.json` 至少记录：

- 任务编号和提示词摘要
- 提示词内容哈希
- 开始、结束时间和耗时
- 成功或失败状态
- HTTP 状态码
- `X-CPA-TRACE-ID`
- 重试次数
- 输出文件路径
- 失败正文的安全摘要

执行器在每张图片结束后原子更新清单，避免进程中断后丢失全部进度。支持显式 `--resume`：根据提示词哈希跳过已经成功且文件仍有效的任务，防止重复消耗额度。

## 可观测性和用户反馈

运行时输出以下进度：

- 当前波次和总波次数
- 本波次任务范围
- 当前成功、失败和剩余数量
- 波次结束后的 3 秒冷却提示
- 等待全局批次锁时的状态

最终答复必须给出输出目录、成功数、失败数和失败原因摘要。部分成功视为批次已完成但存在失败，不能笼统报告为全部成功或全部失败。

## 错误边界

- 缺少 API Key：请求前失败，不创建网络任务。
- 提示词为空、数量不一致或发现乱码：预检失败，不发送任何请求。
- 单张失败：记录后继续等待本波次其他任务。
- CPA 响应缺少有效 `b64_json`：记录响应结构错误，不下载响应中未经信任的任意 URL。
- 全局锁等待：保持排队状态，不启动第二套并发请求。
- 用户中止：停止尚未开始的波次，尽力取消当前请求，保存现有清单并释放锁。

## 验证策略

先进行不消耗生图额度的验证：

1. 基线测试：不加载 Skill 时，让独立代理处理“批量生图”请求，记录其是否遗漏超时、波次、乱码和失败隔离。
2. 触发测试：验证“批量生图”“根据文案生成 20 张配图”等表达会选择本 Skill。
3. 模拟 HTTP 服务：返回可控的成功、429、503、超时和 `context canceled` 响应。
4. 波次测试：23 个任务必须严格表现为 `10 → 等待 3 秒 → 10 → 等待 3 秒 → 3`，任意时刻在途请求不超过 10。
5. 全局锁测试：两个并行执行器不能同时进入请求波次。
6. 超时测试：配置值必须为 180 秒，模拟慢响应不能在约 34 秒被内部取消。
7. 重试测试：`context canceled` 不重试，429/503 最多重试一次。
8. 编码测试：正常中文原样到达模拟服务，已知 mojibake 输入在网络请求前被拒绝。
9. 恢复测试：中断后使用 `--resume` 只补失败或缺失项目。
10. Skill 结构使用官方 `quick_validate.py` 验证。

模拟验证全部通过后，只执行一次简单、低质量、`1024x1024` 的真实 CPA 生图请求，确认真实响应解码和落盘。不得以验证为由批量消耗账号额度。

## 验收标准

- 用户说“批量生图”时能够发现并加载 `cpa-batch-image`。
- 提示词列表与文案拆图两种模式都能形成有效输入。
- 单批最多 10 个请求，整批全局并发不超过 10。
- 每批全部结束后仅在仍有下一批时等待 3 秒。
- 单请求真实等待上限为 180 秒，不再出现 Skill 自身制造的固定 34 秒取消。
- 中文提示词通过网络后保持一致，乱码请求不会发送。
- 单张失败不影响其他图片，重试规则无重复额度风暴。
- 输出图片、提示词和清单可以定位、恢复和审计。
