## 同行文案二创：已定位的问题

### 用户现象

- 用户不知道在哪个项目步骤输入同行原文。
- 在普通 Codex 对话中生成文案后，项目中看不到生成文案。
- 项目缺少正式文案资产，因此无法进入下一步。

### 根因

系统存在两条不同路径：

1. **普通 Codex 对话**：用于聊天、讨论和追问；回复不会自动登记为项目资产，不会生成 `continuous_script`，也不会解锁下一步。
2. **正式项目二创任务**：绑定项目资产和任务 manifest；成功后登记 `continuous_script`，存在该资产后才能进入“配音字幕”等下一阶段。

因此，聊天中有文案不代表项目中存在可用于生产流程的正式连续文案。

### 爆款库的影响

爆款库未启动仅影响从爆款库检索文章和查询文章信息。

它**不应影响**手动粘贴同行原文、保存到项目、启动正式二创任务、生成项目连续文案。

## 正确目标流程

```text
项目
  → 第 1 步「文案生成」
  → 粘贴同行原文
  → 保存为 source_script（爆款原文）项目资产
  → 创建 remix.standard 正式二创任务
  → 任务完成
  → 登记 continuous_script（连续文案）项目资产
  → 自动解锁第 2 步「配音字幕」
```

规则：普通 Codex 对话仅用于讨论，不写入项目资产，也不解锁下一步；只有正式任务输出的 `continuous_script` 才是流程认可的连续文案。

## 源码层已完成、但尚未发布的同行文案功能

> 以下修改已完成源码层测试与验证，但尚未执行发布嵌入构建、服务重启和运行中版本核验；当前 `2030` 服务不应被视为包含这些功能。

### 后端

文件：`internal/httpapi/projects.go`

- 已允许 `source_script` 作为可上传的项目资产类型。
- 同行原文可保存为当前项目的正式“爆款原文”资产。
- 上传会绑定当前项目版本，并维持源资产到正式任务及其输出的血缘关系。
- 同一活动任务会幂等复用，避免重复创建相同的正式二创任务。

### 工作台入口

文件：`web/src/project-workbench/ProjectWorkbench.tsx`

- 在 `script`（文案生成）阶段显示“同行原文输入”区域。
- 提供“同行原文”文本框。
- 提供“保存原文并开始二创”按钮。
- 明确提示普通对话不会写入项目，也不会解锁下一步。

### 前端任务接入

文件：`web/src/App.tsx`

- 原文会提交到：

```text
POST /api/projects/{projectID}/assets/source_script
```

- 保存成功后创建正式项目任务：

```text
POST /api/projects/{projectID}/tasks
```

请求核心字段：

```json
{
  "type": "remix",
  "action": "remix.standard"
}
```

正式任务使用 `source_script` 输入，并应输出 `continuous_script`。工作台入口、上传、任务创建、版本绑定、幂等和血缘均已有对应源码层测试覆盖。
