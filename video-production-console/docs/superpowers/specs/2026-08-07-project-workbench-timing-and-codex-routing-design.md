# 视频项目一屏制作台、任务耗时统计与 Codex 归类设计

日期：2026-08-07

状态：产品设计已确认，等待书面规格复核

目标系统：`video-production-console`

## 1. 设计结论

控制台把项目详情从侧边抽屉改为独立的一屏制作台。一个视频项目只展示该项目自己的文案、配音、SRT、剪映草稿、成片、Codex 对话和任务进度。项目制作主线统一为：

```text
二创文案 → 上传配音与 SRT → 生成混剪 → 成片审核 → 已发布
```

本次设计同时增加两项底层能力：

1. 为选题、二创和混剪任务记录准确的排队时间、实际执行时间和分步骤耗时。
2. 将控制台自动创建的 Codex 后台线程归入用户已有的“杂项”项目，避免继续污染“视频号混剪”项目。

本设计增量覆盖此前项目详情、制作阶段、口播稿、任务进度、剪映草稿显示名和 Codex 后台线程工作目录的相关设计。登录、账号固定背景图、素材版本、App Server 对话、MCP、Obsidian、爆款库和严格混剪登记契约继续有效。

## 2. 范围与非目标

### 2.1 本次范围

- 项目详情改为独立路由和整页工作台。
- 首屏展示制作主线、当前素材、Codex 对话和当前任务耗时。
- 删除口播稿资产、操作、必需条件和界面文案。
- 删除项目内“给我选题”和“待发布”阶段。
- 将“生成选题卡”和“二创文案”合并为一个用户操作。
- 成片审核提供“已发布”操作。
- 剪映草稿使用可读显示名。
- 新增任务阶段耗时的持久化、实时推送、统计和历史查看。
- 新增 Codex 后台线程归类设置、可读线程名称和旧线程安全迁移。
- 桌面与手机端使用同一业务流程，并针对小屏重新排版。

### 2.2 明确不在本次范围

- 自动打开微信视频号或自动发布视频。
- 自动启动剪映或执行剪映 UI 自动化测试。
- 移动视频项目资产到“杂项”目录。
- 修改 Codex 私有数据库或 rollout 文件中的项目归属字段。
- 删除旧 Codex 线程、旧任务记录或旧剪映草稿。
- 用 AI 推测不存在的步骤时间。

## 3. 项目一屏制作台

### 3.1 路由与页面结构

项目卡点击后进入持久路由：

```text
/projects/{project_id}
```

项目详情不再使用右侧抽屉或点击遮罩就消失的临时弹层。刷新、返回和切换页面后仍能恢复当前项目。

桌面首屏分为三层：

```text
┌ 项目标题、账号、当前状态、返回项目列表、删除项目 ┐
├ 制作主线：二创文案 → 配音/SRT → 混剪 → 审核 → 已发布 ┤
├ 当前操作与任务耗时 ┬ 当前项目素材 ┬ Codex 项目对话 ┤
└ 技术详情、历史版本和完整任务记录按需展开             ┘
```

页面不得依赖长距离向下滚动才能看到当前项目的核心状态。桌面 1366×768 视口内必须同时看到项目名称、制作主线、下一步操作、素材概况和 Codex 对话入口。

### 3.2 制作主线

制作主线只有五个真实阶段：

1. `二创文案`
2. `配音与字幕`
3. `生成混剪`
4. `成片审核`
5. `已发布`

每个阶段只回答三件事：已有内容、缺少内容、下一步操作。阶段状态来源于项目正式资产和任务状态，不根据按钮点击次数推测。

取消独立的“待发布”列。成片审核通过后，用户点击“已发布”，项目进入已发布筛选；该操作只更新项目发布状态，不自动调用外部发布平台。

### 3.3 手机端

手机端使用单列制作台：

- 顶部显示项目标题、账号和当前状态。
- 制作主线改为纵向紧凑步骤。
- 当前主操作固定在底部安全区上方。
- 素材和 Codex 对话使用页内折叠区，不使用横向三栏。
- 耗时概览默认显示总耗时和最慢三个步骤，点击后展开全部阶段。
- 所有触控目标不小于 44px，支持局域网浏览器操作。

## 4. 操作流程与资产契约

### 4.1 二创文案

项目内只保留一个“二创文案”按钮。它是编排操作，不把两个步骤伪装成一个不可观察的任务：

1. 如果当前项目没有正式 `topic_card`，先执行正式选题卡生成。
2. 选题卡成功登记后，自动执行财经二创。
3. 如果项目已有可用 `topic_card`，直接执行二创。
4. 任一步失败时停止后续步骤，保留已成功的产物并显示失败位置。

界面使用一条连续进度显示“正在生成选题卡”或“正在二创文案”，用户不需要重复点击。选题卡仍写入 Obsidian，并作为项目资料可查看；它不再占用一个独立制作阶段。

### 4.2 配音与 SRT

二创文案确认后，用户上传：

- 配音：`narration`
- 字幕：`subtitle_srt`

账号固定背景图继续继承自账号，不需要每个项目重复上传。界面明确区分“项目素材”和“继承自账号的背景图”。

### 4.3 删除口播稿

`spoken_script` 不再是正式资产、可上传资产、任务前置条件或项目阶段。以下内容全部移除：

- 口播稿按钮和上传选项。
- 口播稿缺失提示。
- 混剪任务对口播稿的依赖。
- 项目素材列表中的口播稿。
- 面向新任务的口播稿生成协议。

数据库中的历史口播稿记录保留只读兼容，不删除文件，不影响旧任务审计。

### 4.4 混剪与成片

混剪输入为：

- 连续版文案 `continuous_script`
- 配音 `narration`
- SRT `subtitle_srt`
- 账号固定背景图 `account_background`
- 机器配置和已验证工程参考

Codex 只生成并校验明文草稿；可信宿主登记到剪映后，才能生成 `ready` 的正式 `mix_draft`。登记失败只允许重试登记，不重跑文案、素材选择或草稿构建。

用户可以上传或登记成片并进入成片审核。审核通过后点击“已发布”。

## 5. 剪映草稿可读命名

剪映显示名和控制台正式草稿资产名使用：

```text
账号名_第一个短标题_UUID后6位
```

示例：

```text
财富觉醒02_存款大搬家_54c78a
```

规则：

- 优先使用二创结果中的第一个短标题。
- 没有短标题时使用项目名称。
- 过滤 Windows 非法文件名字符和首尾空白。
- 对账号名和标题设置长度上限，完整 UUID 后六位始终保留。
- 显示名重复时由 UUID 后六位保证区分。
- 底层任务 ID、草稿目录绑定、草稿 ID、资产主键继续使用完整 UUID。
- 已有合法草稿只更新可读显示信息，不移动目录、不更换草稿 ID、不重新生成内容。

## 6. 任务耗时统计

### 6.1 三个总指标

每个任务固定显示：

- `总耗时`：`finished_at - created_at`；运行中使用当前时间。
- `排队耗时`：第一次实际执行开始时间减去进入调度队列的时间。
- `实际执行耗时`：实际执行开始到最终完成、失败或取消。

任务准备时间为进入调度队列的时间减去创建时间，因此总耗时由任务准备、排队和实际执行共同组成。新任务在 `codex_tasks` 中持久化 `queued_at`；旧任务没有该字段值时，才使用 `created_at` 作为排队起点并标记为估算。

重试登记是同一任务的独立阶段尝试，不覆盖原失败尝试。任务总览显示累计耗时，详细记录显示每次尝试。

### 6.2 通用阶段

所有任务至少记录：

1. `task_prepare`：任务清单生成、输入绑定和配置快照。
2. `queue_wait`：等待并发槽位或项目写入锁。
3. `codex_execution`：Codex turn 实际运行。
4. `result_validation`：结构化结果、产物路径和摘要校验。
5. `asset_commit`：正式资产与项目状态事务入库。

选题和二创任务在可观测时增加：

- `obsidian_dedup`：近 30 天选题卡排重。
- `baokuan_search`：爆款库正式作品与已审核片段检索。
- `web_research`：Grok 或其他允许的联网补充。
- `content_generation`：候选选题、选题卡或二创正文生成整理。

无法从工具开始/结束事件可靠区分的推理时间统一计入 `codex_execution` 或 `content_generation`，不得伪造更细的阶段。

### 6.3 混剪阶段

混剪必须显示：

1. `input_validation`：输入文件、机器配置、工程参考和 manifest 校验。
2. `media_search`：素材库检索和候选片段筛选。
3. `production_plan`：生产方案生成与方案校验。
4. `draft_build`：明文剪映草稿构建。
5. `plaintext_validation`：草稿结构、时长、音频、字幕、画面和素材使用校验。
6. `jianying_registration`：可信宿主剪映登记。
7. `asset_commit`：正式 `mix_draft` 资产入库。

排队等待单独显示，不混入上述执行步骤。

### 6.4 计时数据来源

计时使用宿主时钟和实际事件边界：

- 调度器记录创建、排队、开始和结束。
- App Server 的 item/turn 开始与完成事件记录工具和 Codex 执行区间。
- 确定性混剪脚本输出阶段开始、阶段结束和耗时数据。
- Montage Registrar 记录登记排队、登记执行和资产提交。

浏览器只根据服务端 `started_at` 对当前阶段做本地秒表显示，不把浏览器时间写回数据库。

### 6.5 数据模型

新增 `task_phase_runs`：

- `id`
- `task_id`
- `attempt`
- `phase_key`
- `display_name`
- `source`：`host`、`app_server` 或 `skill`
- `state`：`queued`、`running`、`completed`、`failed`、`canceled`、`interrupted`
- `started_at`
- `finished_at`
- `duration_ms`
- `detail_json`
- `created_at`

约束：

- 同一任务、尝试和阶段同一时间最多一个 `running` 记录。
- 完成时间不得早于开始时间。
- `duration_ms` 由服务端计算，不接受浏览器提交。
- 服务重启时，将无法确认仍在运行的阶段标记为 `interrupted`，不继续虚假计时。
- 历史任务没有分阶段数据时，只显示已有的总耗时、排队耗时和实际执行耗时，并标记“旧任务无步骤统计”。

### 6.6 界面呈现

任务概览：

```text
总耗时 21分43秒   排队 2秒   实际执行 21分41秒
最耗时：草稿构建 12分18秒，占实际执行时间 56%
```

下方使用一条按时长比例分段的时间轨道。当前阶段使用克制的游标动画；已完成阶段保持静态。点击展开后显示阶段、状态、开始时间、结束时间、耗时和失败说明。

统计页面支持按任务类型查看最近任务的阶段耗时中位数和最大值，用于后续优化；首版不做复杂 BI、成本预测或跨机器比较。

## 7. Codex 后台线程归入“杂项”

### 7.1 已确认的项目

```text
项目名：杂项
projectId：4d8d66b0-f80b-4f77-aef3-280a232398a6
路径：C:\Users\prepare\Documents\杂项
```

App Server 的 `thread/start` 不接受 Codex Desktop `projectId`，桌面端主要根据线程工作目录归类。因此控制台使用杂项目录内的稳定工作目录：

```text
C:\Users\prepare\Documents\杂项\video-console-tasks\<视频项目ID>
```

每个视频项目仍拥有独立主线程；共同归入“杂项”不代表共用同一对话。

### 7.2 线程与任务工作目录

新增设置：

- `Codex 后台任务项目路径`
- 默认值：`C:\Users\prepare\Documents\杂项`
- 页面显示检测到的项目名“杂项”和目录可用状态。

创建项目主线程时：

- `thread/start.cwd` 使用杂项下的视频项目子目录。
- `turn/start.cwd` 与线程工作目录一致。
- formal task 的 `workspaceWrite.writableRoots` 同时包含线程工作目录和当前任务 `output_dir`。
- manifest、输入素材、MCP 地址和 Obsidian 路径继续使用绝对路径。
- 全局 Skills 从 `C:\Users\prepare\.codex\skills` 加载，不复制到杂项目录。

启动任务前校验工作目录、输出目录、Skill 快照和必要 MCP。归类目录异常时任务不得静默退回“视频号混剪”，而是显示明确配置错误。

### 7.3 可读线程名称

线程创建或迁移成功后调用 App Server `thread/name/set`。名称格式：

```text
[选题] 账号名｜项目短标题
[二创] 账号名｜项目短标题
[混剪] 账号名｜项目短标题
```

项目主线程承接多种正式任务时，名称使用：

```text
[视频项目] 账号名｜项目短标题
```

不得再让整段英文 manifest 指令成为桌面端任务标题。

## 8. 已有 Codex 线程安全迁移

Codex 没有安全的“原地修改 thread.projectId”接口，禁止修改 Codex 私有数据库。采用“复制到杂项、验证、切换绑定、归档原线程”的迁移方式。

### 8.1 当前项目主线程

对控制台数据库中仍在使用的项目主线程：

1. 只处理 `idle` 或已完成状态；运行中、排队中和等待用户回答的线程暂不迁移。
2. 使用 `thread/fork`，并将新线程 cwd 指向杂项下对应项目目录。
3. 使用 `thread/read` 验证新线程存在并可继续。
4. 调用 `thread/name/set` 设置可读名称。
5. 在数据库事务中切换项目主会话的 thread ID 和工作目录。
6. 再次读取并确认控制台绑定指向新线程。
7. 最后归档原线程，不删除原历史。

任何一步失败都保留原线程和原绑定，不形成双写。

### 8.2 历史自动线程

只处理能够通过 `codex_tasks.codex_thread_id` 或 `chat_sessions.codex_thread_id` 证明由控制台创建的线程：

- 已被新项目主线程替代的旧自动线程归档。
- 当前仍作为项目主线程的线程按 8.1 迁移。
- 用户手动创建的“视频号混剪”对话不自动归档。
- 当前正在讨论和开发控制台的主对话不迁移、不归档。

控制台任务历史继续保存在 SQLite 中，归档桌面线程不会删除项目任务、消息、产物或耗时数据。

## 9. API 与服务边界

新增或扩展：

- `GET /api/tasks/{id}/timings`
- `GET /api/projects/{id}/timing-summary`
- `GET /api/settings/codex-routing`
- `PUT /api/settings/codex-routing`
- `POST /api/codex/routing/migrate`
- `GET /api/codex/routing/migration-status`
- 现有任务 WebSocket 增加 `phase_started`、`phase_completed`、`phase_failed` 和时间字段。

迁移接口只接受预定义操作，不接受浏览器提交任意 thread ID 或文件路径。服务端从已登录用户、控制台数据库绑定和设置快照解析目标。

## 10. 一致性与错误处理

- 二创编排中选题卡成功而二创失败：保留选题卡，项目仍停留在二创阶段，可重试二创。
- 任务阶段事件重复到达：以 task、attempt、phase 和外部 item ID 幂等合并。
- WebSocket 断线：任务继续，重连后按序号补发阶段和耗时。
- 控制台重启：已持久化完成阶段不变；无法确认的运行阶段标记中断。
- 混剪登记失败：保留明文草稿和各阶段耗时，只重试登记并新增尝试。
- Codex 线程迁移失败：保持原绑定，显示失败步骤，允许稍后重试。
- 杂项目录不可写：不创建新线程，不回退到错误项目。
- 旧任务没有阶段记录：显示总耗时，不生成虚假的细分时间。

## 11. 视觉系统

界面延续“单人视频制作台”，避免通用企业后台卡片堆叠：

- 使用冷灰工作台背景、深墨文字、绿色完成状态、琥珀色等待状态和单一暖色游标。
- 制作主线和耗时轨道使用同一种“时间线”视觉语言，结构表示真实顺序和时长。
- 只在当前阶段游标使用一次克制动画，并支持 `prefers-reduced-motion`。
- 全部图标使用 Lucide，统一线宽和尺寸，不使用 Emoji 或混合图标库。
- 技术日志、原始 JSON 和路径默认折叠；用户首先看到中文状态、产物和下一步。
- 错误信息说明失败步骤、已保留内容和可执行动作，不显示无解释的英文异常。

## 12. 测试与验收

### 12.1 项目工作台

- 项目详情为独立路由，刷新和返回不丢失项目。
- 1366×768 首屏能看到主线、下一步、素材概况和对话入口。
- 手机端单列布局、固定底部操作和安全区正确。
- 页面不显示口播稿、项目内选题按钮或待发布阶段。
- “二创文案”能按是否存在选题卡正确编排任务。
- 已发布操作只更新状态，不调用外部平台。

### 12.2 资产与混剪

- 混剪只要求连续文案、配音、SRT、固定背景图和工程配置。
- 历史口播稿仍可审计，但不影响新任务。
- 草稿显示名符合命名规则，底层 UUID 和草稿 ID 不变。
- 登记失败只重试登记，不重建草稿。
- 正式草稿必须登记和校验成功后才为 `ready`。

### 12.3 耗时统计

- 创建、排队、运行、完成、失败、取消和重启中断均有确定结果。
- 总耗时等于排队与实际执行的时间边界关系，不出现负值。
- 混剪七个执行步骤可分别显示，缺少可靠事件时不伪造数据。
- 重试登记保留原尝试并新增尝试。
- 浏览器刷新后当前步骤秒表继续正确显示。
- 历史任务显示“旧任务无步骤统计”。

### 12.4 Codex 归类

- 新项目线程 cwd 位于杂项目录的项目子目录。
- formal task 可以读取绝对输入并只写任务 output 目录。
- 全局 Skill、爆款库 MCP 和 Obsidian 仍可使用。
- 线程标题为中文可读名称，不是整段任务提示词。
- 空闲项目主线程可 fork、验证、切换并归档原线程。
- 活动线程不会被迁移或中断。
- 迁移失败不改变原绑定，不修改 Codex 私有数据库。

## 13. 实施边界

代码施工分为四个可独立验收的工作包：

1. 项目一屏制作台、流程精简、口播稿移除和已发布状态。
2. 草稿可读命名及现有合法草稿显示名补写。
3. 阶段耗时数据模型、后端埋点、混剪脚本计时、API 和 UI。
4. Codex 杂项路由、双写入根、可读线程名和旧线程迁移。

第 3、4 包可以在第 1 包基础稳定后并行施工。任何工作包都不得中断当前正在运行的 Codex turn，不得自动启动剪映或微信视频号。

本规格没有待定产品选项。书面规格复核通过后，下一步是编写逐文件、逐测试的代码实施计划。
