# 图文项目一键生成与发布信息体验设计

日期：2026-08-14
状态：已确认，待实施计划

## 1. 背景与目标

当前图文模式要求用户依次生成分段、确认分段、生成图片提示词并启动生图。流程暴露了过多中间步骤，刷新和项目导航还可能触发重复详情请求，造成已经打开的项目被瞬时 404 覆盖。图片客户端虽然已有固定的一次重试，但用户无法配置总尝试次数。发布候选功能已经具备标题、描述、编辑、复制和保存能力，但弹窗尺寸与信息层级不适合桌面生产。

本次改造的目标是：

- 默认提供“一键生成”，用户粘贴文案后直接得到可发布的图片项目。
- 保留现有分段编辑流程，作为“高级手动模式”。
- 允许设置每张图片的总尝试次数，默认 2 次。
- 允许部分图片失败，不因单图故障阻断整个项目。
- 修复同一项目重复加载造成的假 404，并支持刷新后恢复进度。
- 重做“图文标题及描述”为宽版双栏编辑台。
- 由 AI 生成项目名称和 5 条发布候选；每条描述末尾包含 3–5 个相关话题。

## 2. 已确认的产品决策

### 2.1 默认流程

图文入口默认进入一键生成工作台。页面采用“焦点工作台”布局：左侧是大文案输入区，右侧是紧凑参数栏，底部是四阶段进度。用户无需填写项目名称，也无需查看或确认分段和提示词。

高级手动模式保留现有能力，供需要修改分段或逐条调整提示词的用户使用。两种模式最终进入同一种项目详情页，共用图片列表、单图重生成、发布信息和打包下载能力。

### 2.2 图片尝试次数

设置值表示包含首次请求在内的总尝试次数：

- `1`：最多请求 1 次，不重试。
- `2`：最多请求 2 次，即首次失败后最多再请求 1 次。
- 允许范围：`1–4`。
- 默认值：`2`。

全局设置提供默认值。一键生成的“高级参数”显示该默认值并允许按项目覆盖。项目持久化最终采用的值，保证刷新后继续生成、单图重生成和批量补生成使用同一语义。高级手动项目未显式设置时使用全局默认值。

### 2.3 部分成功

批量生图按图片项独立执行和计数。若 11 张图片成功 9 张、失败 2 张，项目仍可完成并交付：成功图片正常预览和下载，失败项保留在原位置，显示最终错误和“重新生成”操作。

生图接口返回多个 URL 时，只选取 `urls[0]` 作为该图片项的结果。

## 3. 页面与路由

### 3.1 路由

- `/image-projects`：默认一键生成工作台或项目列表入口。
- `/image-projects/advanced`：高级手动模式。
- `/image-projects/{id}`：统一项目详情地址。

创建项目后立即导航到项目详情地址。刷新详情页时根据 URL 中的项目 ID 恢复项目及运行状态，不回退到控制台主页。

### 3.2 一键生成工作台

左侧文案区是页面视觉焦点。右侧只展示日常需要的参数：

- 思考强度。
- 图片比例。
- 视觉风格。
- 项目并发数。
- 图片模型。

“高级参数”包含图片总尝试次数，初始值来自全局设置。除文案外，其余字段均提供当前配置中的默认值。项目名称由文本模型根据文案生成，创建后仍可编辑。

主操作只有“开始生成图片”。提交后隐藏分段和提示词内容，只显示：

`分析文案 → 生成提示词 → 生成图片 4/11 → 完成 9/11`

### 3.3 发布信息编辑台

项目详情页在“打包下载”左侧提供“图文标题及描述”按钮。弹窗采用已确认的宽版双栏布局：

- 桌面端目标宽度约 960px，最大宽度受视口约束。
- 左侧展示 5 条候选，可快速切换。
- 右侧提供大尺寸标题和描述编辑区。
- 标题最多 22 个字符。
- 描述最多 1000 个字符，计数包含话题标签。
- 每条描述末尾由 AI 生成 3–5 个与文案相关的话题，例如 `#存款 #财富管理 #思维提升 #干货分享`。
- 支持复制标题、复制描述、复制全部和保存当前候选。
- 窄屏切换为单栏，候选列表位于编辑区上方。

发布候选不阻断图片主流程。若候选生成失败，图片仍可完成，项目详情显示单独的发布信息重试入口。

## 4. 后端编排设计

### 4.1 接口边界

新增 `POST /api/image-projects/quick-generate`。请求包含：

- 原始文案。
- 思考强度。
- 图片比例。
- 视觉风格。
- 项目并发数。
- 图片模型。
- 可选的项目级图片总尝试次数。

API Key、文本模型地址等敏感或服务端配置继续由设置服务读取，不传回浏览器。

接口先校验输入并持久化项目，再返回 HTTP 202 和项目 ID。后续模型调用与生图使用独立于浏览器请求的工作上下文，浏览器刷新或断开不会取消运行。

现有项目详情接口返回运行状态和进度。另提供项目级“继续生成”操作，用于阶段失败或服务重启后从最后一个安全检查点继续。必须通过项目状态或互斥机制拒绝同一项目的重复并发运行。

### 4.2 阶段和检查点

一键编排服务按顺序执行：

1. `planning`：分析文案，生成项目名称、完整分段和 5 条发布候选。
2. `prompting`：为确认后的分段生成图片提示词并持久化图片项。
3. `imaging`：按项目并发数生成图片，并逐项保存成功 URL、尝试次数和最终错误。
4. `completed`：汇总成功数和失败数，项目进入可交付状态。

每个阶段开始、完成或失败时都更新项目状态和时间。项目至少持久化：运行模式、当前阶段、运行状态、图片总数、成功数、失败数、阶段错误、最后更新时间和项目级总尝试次数。

浏览器刷新只重新读取这些状态，不重新创建项目，也不重复执行已完成阶段。服务进程重启后，遗留的运行中项目标记为“已中断”，用户可从最后一个已完成检查点继续，而不是静默重复请求。

### 4.3 模型输出约束

规划阶段继续要求结构化 JSON，并验证分段完整覆盖原文。解析器可以移除 Markdown 代码围栏并提取唯一 JSON 对象，但不得把普通说明文字当成有效结果。

AI 项目名称缺失或不符合限制时，使用原文首个有效短句生成确定性回退名称，不能因名称问题阻断分段和生图。

发布候选单独校验标题长度、描述长度和话题数量。候选无效时记录发布信息错误，不阻断图片主流程。图片提示词沿用已确定的图文规则：允许在适合的信息图或关键解释画面中加入少量、清晰、足够大的中文标题或说明，不要求每张图片都带文字，也不得堆叠大段小字。

## 5. 重试与错误恢复

### 5.1 图片重试分类

以下瞬时错误可在项目总尝试次数范围内自动重试：

- HTTP 429、502、503、504。
- EOF、连接重置或上游提前断开。
- 网络连接和读取超时。

以下错误不自动重试：

- HTTP 400 等明确的请求参数错误。
- HTTP 401、403 等鉴权或权限错误。
- 用户取消或服务主动停止。
- 其他明确判定为永久错误的响应。

每个图片项独立计数。达到总尝试次数后保存最后一次错误，供页面展示和人工重生成。

### 5.2 阶段失败

- 分段失败：保存原文和所有参数，显示“分析文案失败”，允许重试规划阶段。
- 提示词失败：保留项目、分段和发布候选，从提示词阶段继续。
- 生图失败：保留成功图片，只补生成失败项。
- 发布候选失败：图片流程继续，单独重试发布信息。

页面错误必须展示阶段和上游详情，不再把网络断开、模型 JSON 无效和业务校验失败合并为同一个笼统提示。

## 6. 假 404 修复

当前项目打开流程可能先成功加载详情，随后因 URL 变化再次加载同一 ID；第二次瞬时 404 会覆盖已经成功的详情。

修复规则：

- 项目持久化完成后才向创建请求返回 ID。
- 打开项目时由 URL 状态作为唯一加载源，避免 `openProject` 和路由 effect 同时请求同一 ID。
- 对相同项目 ID 的进行中请求去重。
- 页面已经持有同一 ID 的有效详情时，后续瞬时 404 不得覆盖成功状态。
- 真正不存在且没有任何已加载详情的项目仍展示标准 404，不做无限重试。

## 7. 兼容性与迁移

新增项目字段必须允许旧数据为空。读取旧项目时按高级手动项目处理，并根据已有图片项推导展示状态；旧项目继续支持打开、单图重生成和打包下载。

设置服务、设置白名单、公开设置结构和 JSON Schema 同步增加图片总尝试次数。并发数和尝试次数是两个独立字段，不能复用或相互覆盖。

本次不引入 Redis、外部消息队列或新的部署服务。异步编排由现有进程内服务执行，数据库状态负责浏览器刷新恢复和服务重启后的人工续跑。

## 8. 测试与验收

### 8.1 后端

- 设置值为 1 时只调用一次；设置值为 2 时总共最多调用两次。
- 瞬时错误重试，永久错误和取消不重试。
- 多 URL 响应只保存第一张。
- 11 张中 9 张成功时项目进入完成状态，并准确记录 9 成功、2 失败。
- 一键接口先持久化项目再返回 202，阶段转换和检查点正确。
- 阶段重试不会重复已完成工作，同一项目不能并发启动两个编排任务。
- 旧项目在迁移后仍能读取。
- 项目名称回退不会阻断图片流程。
- 发布候选不合规时不会阻断图片流程。

### 8.2 前端

- 默认展示一键工作台，高级手动模式可进入且原流程不回归。
- 创建后进入 `/image-projects/{id}`，刷新保持当前项目。
- 相同 ID 不重复加载，成功详情不被瞬时 404 覆盖。
- 进度条正确展示四阶段、图片完成数和部分失败结果。
- 图片总尝试次数显示默认值并支持 1–4 的项目级覆盖。
- 宽版发布弹窗能切换、编辑、复制和保存 5 条候选。
- 候选标题不超过 22 字，描述末尾包含 3–5 个相关话题。
- 桌面端、窄屏和键盘操作无横向溢出，交互控件具有可见焦点。

### 8.3 端到端验收

粘贴一篇文案并使用默认设置后，用户不操作任何中间步骤即可得到完整项目。项目允许部分图片失败，成功图片可正常下载，失败图片可单独重生成；刷新任何运行中或已完成的项目详情页都不会回到主页或出现假 404。高级手动模式仍能完成原有“分段—确认—提示词—生图”流程。

## 9. 非目标

- 本次不实现跨机器分布式任务队列。
- 本次不自动发布到视频号或其他平台。
- 本次不删除或重写高级手动模式。
- 本次不对所有图片强制加入文字；是否添加文字由画面内容和信息表达需要决定。
