# Skill 清理选择器设计

## 目标

创建一个本地单文件 HTML，完整展示当前机器上的 Skill 与插件包，让用户能够理解用途、查看 Codex Desktop／Codex CLI／视频生产控制台的可见性，勾选拟停用或卸载项，并导出一份供 Codex 审阅的选择结果。

页面不执行停用、移动、删除或插件卸载。任何实际变更都必须经过“用户勾选 → Codex 复核并列出精确目标 → 用户再次明确确认”三步。

## 盘点范围

- 159 份非插件 `SKILL.md`，去重后 144 个 Skill 名称。
- 15 组同名重复项，其中 13 组内容不同。
- 18 个插件缓存包，包含 54 份插件内 Skill。
- 页面以实际安装实例为最小选择单位，因此同名 Skill 的不同路径分别显示。
- 插件以插件包为选择单位；插件内部 Skill 只作为展开详情，不单独冒充可卸载插件。

## Codex CLI 与 Desktop 边界

根据当前 Codex Manual：

- Codex CLI 的常规用户级 Skill 目录是 `$HOME/.agents/skills`。
- 仓库级 Skill 位于从当前工作目录到仓库根目录各层的 `.agents/skills`。
- 同名 Skill 不会合并，两个实例都可能出现在选择器中。
- Skill 使用渐进式加载：先加载名称与描述，选中后才读取完整 `SKILL.md`。
- 可以在 `~/.codex/config.toml` 中通过 `[[skills.config]]` 和 `enabled = false` 可逆禁用，而不删除文件。

当前机器还存在以下本地事实：

- Codex Desktop 当前会话可发现 `C:\Users\prepare\.codex\skills` 和 `C:\Users\prepare\.agents\skills` 中的多项 Skill。
- 视频生产控制台源码只注册 `finance-topic-selector`、`finance-viral-remix`、`jianying-montage-draft`，并直接依赖 `C:\Users\prepare\.codex\skills` 下的核心副本。
- 因此页面不得把 `.codex\skills` 与 `.agents\skills` 简化为完全互通，也不得自动选择核心三项。

页面为每个安装实例显示以下兼容性标记：

- `CLI 用户目录`：位于 `C:\Users\prepare\.agents\skills`。
- `Desktop 当前可见`：本次 Desktop Skills 清单已发现。
- `控制台硬依赖`：属于核心三项且控制台注册表使用。
- `插件贡献`：由已安装或缓存插件提供。
- `磁盘存在但本会话未暴露`：文件存在，但当前 Skills 清单没有对应条目。

## 推荐等级

每个项目使用一个明确等级：

1. `必须保留`：核心三项和会破坏控制台的依赖；复选框锁定。
2. `建议保留`：核心质量门、当前开发验证工具和必要的上游生产工具。
3. `按需保留`：只有特定场景使用，例如下载、TTS、图片、浏览器、GitHub 或办公文档。
4. `推荐停用`：与当前视频号财经生产链无关、功能被核心 Skill 替代，或属于另一套视频生产体系。
5. `需人工比较`：同名但内容不同的重复副本；不得被一键选择。
6. `系统管理`：OpenAI 系统 Skill 或运行时包；不得被默认卸载。

“一键勾选推荐停用”只选择第 4 类，并排除：

- 核心三项；
- 系统管理项；
- 同名不同内容项；
- 当前无法确认是否启用的插件运行时；
- 任何被项目控制台源码直接引用的路径。

## 页面结构

页面采用“视频制作资产审计台”方向：冷灰底、墨蓝正文、安全黄色审核标记、珊瑚红停用标记、苔绿色保留标记。Skill 名称与路径使用等宽字体，中文说明使用系统无衬线字体。

页面顶部是固定审计条，显示总实例数、推荐停用数、当前勾选数和风险项数。主体使用左侧筛选轨道与右侧清单，不采用泛化统计仪表盘。

主要区域：

- 搜索：按名称、描述、路径和类别过滤。
- 范围：全部、Skill、插件、重复项、核心链路。
- 建议：必须保留、建议保留、按需保留、推荐停用、需人工比较。
- 环境：CLI 用户目录、Desktop 当前可见、控制台硬依赖、插件贡献。
- 操作：一键勾选推荐停用、只勾选重复的完全相同副本、清空、仅看已选。
- 清单行：复选框、名称、用途、来源路径、兼容性标签、推荐等级、推荐原因。
- 详情抽屉：完整路径、同名实例、内容哈希状态、影响说明和安全备注。
- 底部交接条：导出 JSON、复制清单、生成审阅摘要。

窄屏下筛选区折叠为顶部筛选按钮，清单保持单列并保留可见焦点。

## 选择结果与数据流

页面使用 `localStorage` 自动保存勾选状态、筛选条件和最后更新时间。它同时提供两种交接方式：

1. 导出 `skill-removal-selection.json`，包含审计版本、生成时间、安装实例路径、项目类型、建议等级、用户选择和原因。
2. 复制纯文本清单，适合直接粘贴回 Codex。

当用户说“勾选好了”时，Codex 优先读取仍打开页面的本地状态；无法读取时，再读取导出的 JSON。读取后只生成拟变更清单，不执行变更。

## 后续安全变更流程

1. Codex 读取选择结果并重新核对路径、是否仍存在、是否为核心依赖、是否有同名实例。
2. Codex 分别列出：可逆禁用、移动到停用备份目录、插件卸载、永久删除。
3. 默认建议优先使用 `config.toml` 的 `enabled = false` 或移动到日期化备份目录。
4. 用户再次确认精确列表和操作方式。
5. Codex 执行前建立清单与备份，执行后重新扫描 Desktop 与 CLI 可见 Skill。
6. 插件通过插件管理机制处理，不以删除缓存目录代替卸载。

## 错误处理

- 浏览器不支持下载时显示可复制 JSON 文本。
- `localStorage` 不可用时仍允许本次勾选和导出，并显示状态未持久化。
- 清单数据缺少描述时显示“未提供说明”，不虚构用途。
- 路径或插件状态在勾选后变化时，后续 Codex 复核必须阻止执行并重新生成清单。

## 验证范围

实现前先创建失败测试，覆盖：

- 一键选择只选择 `推荐停用` 且可选的项目。
- 核心、系统和需人工比较项不可被批量选中。
- 搜索、分类、环境筛选可以组合。
- 勾选状态可持久化和恢复。
- 导出 JSON 包含精确实例路径和插件标识。
- 清空与“仅看已选”行为正确。
- 页面可在无网络、无构建工具的 `file://` 场景运行。
- 键盘焦点、移动端布局和 `prefers-reduced-motion` 可用。

最终使用本地浏览器做功能验证和截图审查；不执行任何卸载动作。
